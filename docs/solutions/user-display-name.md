# 统一用户名称

用户填写一个“名称”，可以是真实姓名或昵称。保存时去掉首尾空白，保留内部空格和用户输入顺序；新输入必须为 1–100 个 Unicode 字符。名称不要求唯一，登录仍使用邮箱。

## 覆盖范围

- 初始化管理员、邀请注册、管理员新增/编辑用户、个人资料。
- 系统用户和项目成员列表、名称筛选、侧栏及头像文字。
- API Key 创建者、请求调用者、用户选择框及确认弹窗。
- 用户用量统计、仪表盘和企业统一登录（OIDC）。

系统用户搜索使用后端 `nameContainsFold`。项目成员接口目前一次返回全量成员，不接受过滤参数，因此名称搜索在已经返回的成员中进行。

## 接口契约

| 位置 | 字段 |
| --- | --- |
| User、UserInfo、登录返回、个人资料及用户创建/更新 | `name` |
| 初始化管理员 | `ownerName` |
| 邀请注册 | `name` |

GraphQL 不再提供 `firstName` / `lastName` 或对应输入、筛选字段；初始化 REST 请求也改用 `ownerName`。前后端及调用这些管理接口的脚本需要一起升级。

第三方登录优先采用提供方的完整 `name`；缺失时才合并 `given_name` / `family_name`。创建账户时再缺失则使用邮箱；同步时没有提供名称则保留已有名称。提供方有名称时仍按原有规则同步资料，可能覆盖本地编辑的名称。

## 已有数据升级

1. Ent 自动迁移新增 `users.name`，保留原 `first_name`、`last_name` 列；旧列只作为迁移来源，不再用于业务读写。
2. 启动时，在结构迁移完成后运行 `BackfillUserNames`。它独立于上游版本号，避免 fork 从较新上游版本升级时跳过自己的迁移。
3. 仅补齐名称为空的用户，包含软删除用户；已经设置的新名称不会被覆盖。迁移在事务中分批处理。
4. 中文等 CJK 姓名按“姓＋名”合并；其他姓名按“名＋空格＋姓”合并。只有一个部分则保留该部分，两者为空则使用邮箱。
5. 迁移保留旧数据，不按新输入的 100 字限制截断。MySQL 名称列预留 512 字符，容纳原两个各 255 字符的姓名列及分隔空格。
   编辑其他资料时允许保留未修改的超长旧名称，并省略修改请求中的名称字段；真正改名时再应用新限制。
6. 后端用户缓存改用新版本键，浏览器放弃旧结构用户缓存并用保留的登录令牌重新读取资料。

关闭自动迁移的部署应先完成相同的结构更新和数据回填，再启用新版服务。

不要在后续清理或合并上游时直接删除旧列或已部署的迁移路径。回到旧版程序也不会自动把新名称拆回旧列，因此切回旧镜像不是完整的数据回滚方案。

## 验证

- 后端：名称验证、用户资料读写、缓存隔离、OIDC 创建和同步、两处统计、HTTP 初始化和邀请注册、GraphQL 查询和修改。
- 迁移：真实无 `name` 列的 SQLite 升级、软删除用户、长旧名称、跨批次回填、再次启动保留新昵称。
- 前端：统一名称显示、Unicode 长度、头像文字和旧缓存行为；对应 E2E 用例使用名称字段和稳定选择器。
